# FIRST — критерії якості юніт-тесту

`FIRST` — п'ять властивостей, яким має відповідати кожен юніт-тест. Нижче
кожна властивість подана не як гасло, а як **правило з перевіркою**: що робити,
як переконатися, що саме заборонено.

Тест, який порушує хоча б одну властивість, не вважається виконаним. Порушення
фіксується в `test-report.md`, а не замовчується.

---

## F — Fast (швидкий)

**Правило**: один тест виконується за одиниці мілісекунд. Увесь набір —
за секунди.

**Як досягається**: юніт-тест торкається лише коду в пам'яті. Жодних мережевих
викликів, звернень до БД, `sleep`, таймерів реального часу, підняття HTTP-сервера.

**Заборонено**
```js
await fetch('http://localhost:3000/checkout');   // це інтеграційний тест
await new Promise(r => setTimeout(r, 500));      // штучна затримка
```

**Перевірка**: `node --test` друкує тривалість кожного тесту. Будь-який тест
понад **50 мс** потребує пояснення в звіті.

**Чому це важливо**: повільний набір перестають запускати часто, і він
припиняє бути зворотним зв'язком. Швидкість — не оптимізація, а умова
використання.

## I — Independent (незалежний)

**Правило**: тести не залежать один від одного й від порядку виконання.
Будь-який тест можна запустити поодинці.

**Як досягається**: жодного спільного змінюваного стану між тестами. Дані
створюються всередині тесту. Немає «спочатку тест А щось налаштує, а тест Б
цим скористається».

**Заборонено**
```js
let cart = [];                    // спільний стан на рівні файлу
test('a', () => { cart.push(...) });
test('b', () => { assert.equal(calculateTotal(cart), 10) });  // залежить від 'a'
```

**Дозволено**
```js
test('b', () => {
  const cart = [{ price: 10, quantity: 1 }];   // власні дані тесту
  assert.equal(calculateTotal(cart), 10);
});
```

**Перевірка**: запусти окремий тест за назвою й переконайся, що він проходить:
```bash
node --test --test-name-pattern="назва тесту"
```

## R — Repeatable (відтворюваний)

**Правило**: той самий тест дає той самий результат — завжди, на будь-якій
машині, у будь-який момент.

**Як досягається**: жодних недетермінованих джерел. Заборонені `Date.now()`,
`new Date()`, `Math.random()`, залежність від часового поясу, локалі, змінних
середовища, порядку файлів у каталозі, доступу до мережі.

**Заборонено**
```js
assert.equal(applyDiscount(Math.random() * 100, 10), ???);  // вхід невідомий
assert.ok(result.createdAt <= Date.now());                  // залежить від годинника
```

**Якщо недетермінізм неминучий**: значення передається як параметр або
підміняється, а не зчитується всередині тесту.

**Перевірка**: прогнати набір двічі поспіль — результат ідентичний.

---

## S — Self-validating (самоперевірний)

**Правило**: тест сам виносить вирок — pass або fail. Людина не читає вивід,
щоб вирішити, чи все гаразд.

**Як досягається**: кожен тест закінчується твердженням (`assert`). Жодних
`console.log` як способу перевірки. Жодних тестів без асертів.

**Заборонено**
```js
test('перевірка суми', () => {
  console.log(calculateTotal(items));   // «подивлюсь очима» — це не тест
});
```

**Обов'язково**: перевіряй конкретне значення, а не факт відсутності падіння.
```js
assert.equal(calculateTotal(items), 35);       // ✅ конкретне очікування
assert.ok(calculateTotal(items));              // ❌ пройде і для 15, і для 35
```

**Для помилок** — перевіряй тип і повідомлення, а не сам факт винятку:
```js
assert.throws(() => applyDiscount(35, 150), RangeError);
assert.throws(() => loadCoupon('a/b'), /invalid coupon code/);
```

## T — Timely (своєчасний)

**Правило**: тест пишеться разом зі зміною, яку він покриває, а не «колись потім».

**У контексті цього пайплайну** це означає буквально: генеруються тести
**лише для коду, зміненого в `fix-summary.md`**. Не для всього проєкту.

**Заборонено**
- писати тести для коду, якого не торкався Bug Fixer
- дублювати вже наявні тести з `tests/`
- «заодно» покривати сусідні функції

**Перевірка перед написанням кожного тесту**: чи є цей файл і ця функція
в переліку змін `fix-summary.md`? Ні → тест не пишеться.

**Чому обмеження**: розростання набору тестів поза межі змін робить незрозумілим,
що саме перевіряє поточний прогін, і ховає регресію серед шуму.

---

## Правила цього проєкту

| Параметр | Значення |
|---|---|
| Фреймворк | вбудований `node:test` — **не додавати** jest, mocha, vitest |
| Асерти | `node:assert/strict` |
| Розташування | `tests/*.test.js` |
| Запуск | `npm test` |
| Іменування | `<функція> <очікувана поведінка>` — напр. `applyDiscount rejects an out-of-range percent` |
| Мова тестів | ESM (`import`), файл проєкту має `"type": "module"` |

**Не змінювати наявні файли тестів.** Нові тести — в окремі файли з суфіксом,
який відрізняє їх від базових (напр. `tests/cart.generated.test.js`), щоб
у звіті було видно, що згенеровано агентом, а що існувало раніше.

## Що покривати для зміненого коду

Для кожної зміненої функції — щонайменше по одному тесту на кожну категорію:

1. **Штатний випадок** — типовий коректний вхід
2. **Межа** — нуль, порожній набір, мінімум і максимум діапазону
3. **Некоректний вхід** — неправильний тип, значення поза діапазоном
4. **Регресія на сам дефект** — вхід, що відтворює початковий баг, із
   перевіркою, що тепер результат правильний

Четверта категорія — найцінніша: саме вона не дає дефекту повернутися.
У назві такого тесту вказуй ідентифікатор дефекту, напр.
`calculateTotal (BUG-001 regression) honours quantity greater than one`.

## Обов'язковий машиночитний блок

`test-report.md` мусить містити цей блок дослівно — його читає скрипт оркестрації:

```
<!-- MACHINE-READABLE VERDICT -->
TESTS_GENERATED: <n>
TESTS_TOTAL: <n>
TESTS_PASSED: <n>
TESTS_FAILED: <n>
FIRST_VIOLATIONS: <n>
SLOWEST_TEST_MS: <n>
GATE: <PASS|FAIL>
<!-- END VERDICT -->
```

`GATE: PASS` дозволено лише за умови `TESTS_FAILED = 0` **і**
`FIRST_VIOLATIONS = 0`.

## Чек-лист самоперевірки перед здачею звіту

Пройди по кожному згенерованому тесту:

- [ ] **F** — виконується < 50 мс, без мережі, БД, таймерів
- [ ] **I** — не залежить від інших тестів; проходить при запуску поодинці
- [ ] **R** — без `Date.now()`, `Math.random()`, локалі, змінних середовища
- [ ] **S** — має `assert` із **конкретним** очікуваним значенням
- [ ] **T** — покриває лише код зі списку змін `fix-summary.md`

Порушення не «виправляється мовчки» — воно фіксується в `test-report.md`
разом із тим, що зроблено далі.
