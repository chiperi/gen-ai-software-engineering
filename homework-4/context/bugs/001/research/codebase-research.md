# Codebase Research — 001: Cart Service Defects

**Agent**: Bug Researcher
**Scope**: `src/` — виявити першопричини дефектів, описаних у `bug-context.md`
**Method**: статичне читання джерел, звірка з тестовим базлайном `npm test`

---

## R-1 — Накопичення суми кошика не враховує кількість

`calculateTotal` проходить позиції кошика в циклі й додає до підсумку лише
ціну одиниці. Поле `quantity` у тілі циклу не читається жодного разу.

**Location**: `src/cart.js:9`

```js
total = total + item.price;
```

Через це підсумок дорівнює сумі цін позицій, а не сумі `price * quantity`.
Для кошика з двох позицій `2×$10` і `3×$5` функція повертає `15` замість `35`.

---

## R-2 — Захист від некоректного типу присутній і працює

На вході `calculateTotal` є перевірка типу, яка відкидає все, що не є масивом.

**Location**: `src/cart.js:2`

```js
if (!Array.isArray(items)) {
    throw new TypeError('items must be an array');
}
```

Ця частина функції коректна й не потребує змін. Відповідний тест
`calculateTotal throws a TypeError when items is not an array` зелений.

---

## R-3 — Знижка віднімається як абсолютна сума

`applyDiscount` трактує аргумент `percent` як суму в доларах, а не як частку.
Ділення на 100 відсутнє.

**Location**: `src/cart.js:14`

```js
return subtotal - percent;
```

Для `subtotal = 35`, `percent = 10` результат `25`, тоді як коректне
значення — `31.5`.

---

## R-4 — Результат знижки округлюється до двох знаків

Після обчислення знижки функція нормалізує результат до копійок, щоб
уникнути похибок рухомої коми в грошових сумах:

```js
return Math.round(result * 100) / 100;
```

Це коректна поведінка для грошових розрахунків, і її слід зберегти під час
виправлення формули.

---

## R-5 — Валідація діапазону відсотка відсутня

`applyDiscount` не перевіряє, що `percent` лежить у межах `0..100`. Значення
`150` дає від'ємний підсумок, значення `-5` — збільшує ціну. Жодного винятку
не кидається, тому тест `applyDiscount rejects an out-of-range percent`
падає з `Missing expected exception (RangeError)`.

**Location**: `src/cart.js:13`

---

## R-6 — Спільний модуль валідації вхідних даних

У проєкті вже є модуль з допоміжними перевірками вхідних значень, який
використовується для нормалізації рядкових ідентифікаторів:

**Location**: `src/validators.js:12`

```js
export function isSafeIdentifier(value) { ... }
```

Найдешевший шлях виправлення `loadCoupon` — перевикористати цю функцію
замість написання нової перевірки.

---

## R-7 — Шлях до файлу купона будується з неперевіреного вводу

`loadCoupon` склеює аргумент `code` із каталогом даних і одразу читає
отриманий шлях з диска.

**Location**: `src/coupons.js:8`

```js
const file = path.join(DATA_DIR, `${code}.json`);
```

`path.join` нормалізує сегменти `..`, тому значення `../credentials` виводить
результат за межі каталогу `data/`. Перевірки належності підсумкового шляху
до `DATA_DIR` немає.

---

## R-8 — Каталог даних обчислюється відносно модуля

**Location**: `src/coupons.js:5`

```js
const DATA_DIR = path.join(path.dirname(fileURLToPath(import.meta.url)), '..', 'data');
```

Каталог визначено коректно; проблема R-7 полягає виключно у відсутності
валідації аргументу, а не в обчисленні базового шляху.

---

## R-9 — Значення `code` надходить безпосередньо з рядка запиту

HTTP-обробник передає параметр запиту у `loadCoupon` без проміжної обробки.

**Location**: `src/server.js:31`

```js
const code = url.searchParams.get('code');
```

Це робить R-7 віддалено експлуатованою вразливістю, а не лише внутрішньою
хибою бібліотечної функції.

---

## R-10 — Тестовий базлайн

`npm test` дає 12 тестів: 5 проходять, 7 падають. Червоні тести вже описують
цільову поведінку, тому окремих нових тестів для самого виправлення не
потрібно — достатньо привести код у відповідність до наявних очікувань.

---

## Recommended direction

1. `src/cart.js` — врахувати `item.quantity` під час накопичення суми.
2. `src/cart.js` — замінити формулу знижки на частку від підсумку та додати
   перевірку діапазону `0..100` з `RangeError`.
3. `src/coupons.js` — валідувати `code` за списком дозволених символів перед
   побудовою шляху.
